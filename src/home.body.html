How the estimate works

Memory needed = model weights + context cache + about 0.5 GB of runtime overhead.

Weights = parameters × bits per weight ÷ 8. A 27B model at Q4_K_M (≈4.85 bits) is about 16.4 GB.

Speed comes from memory bandwidth. Each new token reads every active weight once, so tokens/sec ≈ usable bandwidth ÷ active weight size. Mixture-of-experts (MoE) models only read their active experts, which is why a 35B-A3B model runs like a 3B one.

When a model doesn't fit, llama.cpp and Ollama can keep part of it in system RAM. The part in RAM runs at RAM speed, so we blend the two. On Macs and other unified-memory machines, about 72% of RAM is usable for the model.

Common questions

How much VRAM do I need for a local LLM?

At Q4_K_M, plan on about 0.6 GB per billion parameters plus context. A 9B model fits in 8 GB, 27B–31B models need about 20 GB, and a 70B model needs about 45 GB.

Can I run a model bigger than my VRAM?

Yes, with offload to system RAM, but it slows down. MoE models handle offload far better than dense models.

Does AMD or Intel work?

Yes. llama.cpp supports AMD through ROCm and Vulkan, and Intel Arc through Vulkan and SYCL. Speeds land a bit below NVIDIA at the same bandwidth.
